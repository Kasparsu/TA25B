## 🗂️ Topics Covered

### 1. 📁 A Place for Your Work

Make a directory for the course, and a subdirectory per project inside it, rather than
scattering projects across the disk:

```bash
mkdir ta25b
cd ta25b
mkdir learnfront
cd learnfront
```

**Opening it in VS Code from the terminal:**
```bash
code .
```

`code` is the program; `.` is the argument, and **`.` means "this directory"** (just as `..`
means one directory up). So `code .` is "open VS Code here": much quicker than File → Open
Folder.

---

### 2. 🌐 Picking a Default Browser

A short practical aside: the machines default to Edge, and you'll want your own browser for
development. Install it, then set it as the default in Windows Settings → Default apps.

VS Code needs restarting before it notices the change.

> 💬 Personal preference, openly labelled as such: the point is only that *you* should choose,
> rather than accepting whatever the machine came with.

### 3. ⚙️ Configuring Git

The step that gets forgotten every year, and then causes trouble later:

```bash
git config --global user.name "Kaspar Martin Suursalu"
git config --global user.email "you@example.com"
```

**What's going on here:**

- **`--global`** means *this whole machine* (strictly, this user account), not this project.
  Run it **once per computer** you work on: the classroom PC, a different classroom, your
  machine at home.
- **It is not a login.** Git and GitHub are two separate things. Git records a name and an
  email on each commit; that's all this is.
- **Quotes:** single or double both work. Use your full name, written properly: it's what
  appears on every commit you ever make.
- **The email should be the one your GitHub account knows**, so GitHub can match the commit to
  your profile. If it doesn't match, nothing breaks: your commits just won't be attributed.
