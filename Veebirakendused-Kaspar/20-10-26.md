Moving files breaks imports. The editor offers to update them, but that has not been
reliable lately, so checking by hand is wiser. From inside `pages/` the component is one

```js
import ItemList from '../components/ItemList.vue';
```

`../` means "one folder back". A wrong path does not always shout: the page can just go
white, and the console shows a 404 for the file it could not find.

### 2. 🪟 A Bulma modal, switched on with a `ref`

A **modal** is the box that opens on top of the page: the background goes dark, the content
sits in the middle, and it closes with an X button or a click on the background. A big
image that opens when you click a thumbnail is the classic example. The starting point was
Bulma's image modal (<https://bulma.io/documentation/components/modal/#image-modal>).

Bulma's docs say it plainly: Bulma ships **no JavaScript**. The modal is visible when it has
the `is-active` class and hidden without it. Adding the class by hand shows it, but then it
cannot be closed. This is exactly what a frontend framework is for: keep the state in a
variable, let the page follow.

```js
let modal1Active = ref(false);
```

The first version swapped the whole class string with the **conditional (ternary)
operator**, `condition ? valueIfTrue : valueIfFalse`
(<https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Conditional_operator>).
It is plain JavaScript, a one-line `if ... else`. It works, but repeats `modal` twice. The
`class` attribute has a nicer form in Vue: a normal `class` for the classes that are always
there, plus a `:class` **object** whose keys are switched on when their value is true:

```html
<button class="button is-primary" @click="modal1Active = true">Open Modal 1</button>
<div class="modal" :class="{'is-active': modal1Active}">
    <div class="modal-background" @click="modal1Active = false"></div>
    <div class="modal-content">
        <p class="image is-4by3">
            <img src="https://bulma.io/assets/images/placeholders/1280x960.png" alt="">
        </p>
    </div>
    <button class="modal-close is-large" aria-label="close" @click="modal1Active = false"></button>
</div>
```

`is-active` has a dash in it, and JavaScript object keys with a dash need quotes. The
attribute already uses double quotes, so the key gets single ones.

### 3. 🚫 Props are read-only: `$emit` a `close` event

More modals by copy-paste would be WET again, so the modal went into
`src/components/Modal.vue`. Inside it, `modal1Active` means nothing any more (the component
does not know which modal it is), so it takes an `active` prop instead.

Opening worked, closing did not. The console said why: *Set operation on key "active"
failed: target is readonly*. **A component may read its props but not change them.**
Props flow from the top down, and components can sit inside components inside components.
If any of them could change a prop, nobody could tell where a change came from.

The fix is to tell the parent instead: the component throws out its own **event** with
`$emit`, named after what should happen:

```vue
<script setup>
defineProps(['active']);
</script>

<template>
    <div class="modal" :class="{'is-active': active}">
        <div class="modal-background" @click="$emit('close')"></div>
        <div class="modal-content">
            <slot></slot>
        </div>
        <button class="modal-close is-large" aria-label="close" @click="$emit('close')"></button>
    </div>
</template>
```

The parent listens to it exactly like to a click, with `@`, and changes its own `ref`, which
it is allowed to do:

```html
<Modal :active="modal3Active" @close="modal3Active = false">
```

**Props go down, events come up.**

### 4. 🐻 Placeholder images (and why two of them were the same)

With several modals showing the same placeholder, there is no way to tell whether the right
one opened. An `img` prop fixes that (no colon, because it is plain text), and placeholder
image services give pictures in any size straight from a URL:

- <https://placekittens.com/> and <https://placebear.com/>: put the width and height in the
  URL and you get a cat or a bear of that size.
- <https://picsum.photos/>: real photos, a new random one on every load. Add `?grayscale`
  or `?blur=...` to the URL (combine them with `&`), or use a seed word in the path to get
  the same picture every time.

Two modals with the exact same picsum URL showed the **same** photo, refresh or not. That is
not picsum's fault: the browser sees the same URL twice and reuses the image it already has
instead of asking again. Making the URLs differ by anything at all (the server ignores it)
forces two requests:

```html
<ImgModal :active="modal1Active" @close="modal1Active = false" img="https://picsum.photos/1280/960?r=1"></ImgModal>
<ImgModal :active="modal2Active" @close="modal2Active = false" img="https://picsum.photos/1280/960?r=2"></ImgModal>
```

![Cache](https://api.memegen.link/images/same/picsum.photos~s1280~s960_twice/They're_the_same_picture.png)

### 5. 🎰 Any content in a modal: `v-html` vs `<slot>`

A modal does not have to show a picture. Bulma's **box**
(<https://bulma.io/documentation/elements/box/>) made a good test: a white card that can
hold anything.

The first attempt passed the box's HTML in as a `content` prop. It quickly got messy: double
quotes inside a double-quoted attribute end it early, so everything needs single quotes, and
`{{ content }}` printed the HTML **as text**. The `v-html` directive does render it as HTML
(and needs the element to be empty), but writing a whole Bulma card into an attribute string
is unreadable.

The better way is a **slot**. Whatever is written between the component's opening and
closing tag lands where the component has `<slot></slot>`:

```html
<Modal :active="modal3Active" @close="modal3Active = false">
    <div class="box">I'm in a box.</div>
</Modal>
```

![Slot](https://api.memegen.link/images/rollsafe/Can't_fight_quotes_in_v--html/if_the_content_goes_in_a_slot.png)

### 6. 🖼️ `ImgModal`: a component built from a component

The picture modals came back as their own small component that **uses** `Modal` and puts
the image into its slot:

```vue
<script setup>
import Modal from './Modal.vue';

defineProps(['active', 'img']);
</script>
<template>
    <Modal :active="active">
        <p class="image is-4by3">
            <img :src="img" alt="">
        </p>
    </Modal>
</template>
```

`ImgModal` never mentions `close`, yet closing works. Once you had to catch the event and
emit it again one level up. Today Vue passes the `@close` listener given to `ImgModal`
through to its root element, which is the `Modal` (the teacher compared it to events
bubbling up). The page ended with three buttons: two image modals and one modal with a box.

## ✅ Takeaways

1. **Components go in `components/`, pages in `pages/`**; after a move, fix the import
   paths (`../` is one folder up).
2. **Bulma has no JavaScript**: a `ref` plus `:class="{'is-active': ...}"` makes the modal
   work.
3. **Props are read-only.** Props go down, events come up: `$emit('close')` in the child,
   `@close` in the parent.
4. **Placeholder image services** (picsum, placebear, placekittens) give pictures from a
   URL; identical URLs come from the browser cache, so make them differ.
5. **`<slot>` puts any content inside a component**, much cleaner than HTML in a prop with
   `v-html`.
6. **Components can be built from components**: `ImgModal` is a `Modal` with a picture in
   the slot.
