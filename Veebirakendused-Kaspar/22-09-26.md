## 🗂️ Topics Covered

> 🪄 Do it by hand first, then let a framework do it. The order matters: you cannot
> appreciate what Vue removes until you have written it yourself.

### 1. 🖐️ The DOM by hand

```js
const button = document.querySelector('#add');
const list   = document.querySelector('#items');

button.addEventListener('click', () => {
    const li = document.createElement('li');
    li.textContent = input.value;
    list.appendChild(li);
});
```

Everything is explicit: find the element, make an element, set its text, attach it, and
attach a listener. Nothing happens that you did not write.

The pattern to notice is the one that gets tedious: **state lives in the page**. To know
what is in the list you read the DOM back; to change it you find nodes and edit them. With
three items that is fine. With a filter, a counter and a sort, it stops being fine.

Event reference: <https://www.w3schools.com/tags/ref_eventattributes.asp>

### 2. 🔄 Vue, and what it actually changes

```vue
<script setup>
import { ref } from 'vue'

const items = ref([])
const text  = ref('')

function add() {
    items.value.push(text.value)
    text.value = ''
}
</script>

<template>
  <input v-model="text">
  <button @click="add">Add</button>
  <ul>
    <li v-for="item in items">{{ item }}</li>
  </ul>
</template>
```

The inversion: **state lives in JavaScript, and the page follows it.** You never touch the
DOM. `items` is the truth; the `v-for` is a description of how truth should look.

- `ref()` makes a value reactive: changing it re-renders whatever used it
- `v-model` is two-way binding between an input and a variable
- `@click` is an event listener written where you can see it
- `{{ }}` interpolates

Vue plugin for Vite: <https://github.com/vitejs/vite-plugin-vue/tree/main/packages/plugin-vue#vitejsplugin-vue->

### 3. 🗺️ The landscape, for context only

A quick tour so the names are not mysterious, not a list of things to learn now:

- <https://vuejs.org/>: what we are using
- <https://react.dev/>: the biggest ecosystem
- <https://svelte.dev/>: compiles away, no runtime
- <https://www.solidjs.com/>: React-like syntax, finer-grained reactivity
- <https://angular.dev/>: full framework, opinionated, common in large companies
- <https://jquery.com/>: what everyone used before; you will meet it in old code

They mostly agree on the important idea (describe the UI as a function of state) and
differ in how they detect change and how much they do for you.

## ✅ Takeaways

1. **Hand-written DOM keeps state in the page.** Readable at three items, unmanageable at thirty.
2. **A framework inverts that**: state in JavaScript, page derived from it.
3. **`ref`, `v-model`, `v-for`, `@click`** cover most of what a first Vue component needs.
4. **The frameworks mostly agree** on UI-as-a-function-of-state; they differ in how they
   track change.
