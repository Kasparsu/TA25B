### 1. 🔁 State first, page second

With plain JavaScript the work always started by finding an element in the DOM, then
changing it. Frameworks turn that around: you keep a piece of **state** in JavaScript and
say where it should appear. The ideas (and most of the vocabulary) are the same in React,
Angular and the rest, even if the syntax differs.

Printing a value in the template uses double curly braces, the **mustache** syntax (turn
it sideways and it looks like a moustache):

```vue
<h1>{{ message }}</h1>
```

When something goes wrong, Vue often shows the error right on the page, but not always.
Keep the browser console (Inspect > Console) open while you work.

### 2. ⚡ `ref()` and events

A button gets a click handler with the `v-on` directive, written `v-on:click` or, as
almost everyone writes it, `@click`:

```vue
<script setup>
import { ref } from 'vue';

let message = ref('Hello Vue!');
</script>

<template>
    <button @click="message = 'Hello TA25B!'" class="button is-primary">Click me!</button>
</template>
```

With a plain `let message = 'Hello Vue!'` the click does change the variable, but the page
does not notice. **`ref()`** wraps the value in an object that Vue watches: when it
changes, every place that uses it updates by itself. That is the *reactivity* the
framework names itself after.

Editor tip: if Copilot's autocomplete is on, the Vue completion for `ref` may not show up.
Accept the real completion and the `import { ref } from 'vue'` line is added for you.

### 3. 🔗 Binding values: `:value`, `@input` and `v-model`

Putting `{{ message }}` into an attribute does not work: mustaches are only for content.
Attributes get their values with `v-bind`, short form `:`:

```vue
<input type="text" class="input" :value="message">
```

Now the button changes the text box, but typing in the box does not change `message`.
That direction needs an event. The `input` event fires on every keystroke, and its
`target` is the input element itself, so `event.target.value` is the whole text (the
event's `data` is only the one character typed). First as a function in the script, then
inline with Vue's `$event`:

```vue
<!-- <input type="text" class="input" :value="message" @input="message = $event.target.value"> -->
<input type="text" class="input" v-model="message">
```

The commented line is kept in the code as an example: **`v-model` is exactly that pair**,
a `:value` plus an `@input`, in one directive.

One trap from writing the handler in the script: there, `message = ...` replaces the ref
with a plain string and the magic is gone. Inside `<script setup>` you change
**`message.value`**. In the template you write just `message`.

![ref value](https://api.memegen.link/images/mmm/Writes_message_=_'x'_inside_script_setup/The_ref_loses_its_magic.png)

The template accepts expressions, so the reversed-text example from plain JavaScript is
one line:

```vue
<h1>{{ message.split('').reverse().join('') }}</h1>
```

### 4. 🧩 Bulma form addons

To put the text box and its button side by side, Bulma's form docs have a ready pattern,
**form addons** (<https://bulma.io/documentation/form/general/#form-addons>):

```vue
<div class="field has-addons">
    <div class="control is-expanded">
        <input @keydown.enter="add" v-model="message" class="input" type="text" placeholder="Add item">
    </div>
    <div class="control">
        <button @click="add" class="button is-info">
            Add
        </button>
    </div>
</div>
```

`is-expanded` goes on the `control` wrapper, not on the input, and makes the text box take
the remaining width.

Bulma resets the default styles of lists and headings, which is why a `<ul>` showed no
bullets. Wrapping the content in a **`content`** class brings normal typography back.

### 5. 📋 A shopping list with `v-for`

The list itself is a ref holding an array:

```js
let items = ref(['Piim', 'Viin', 'Õlu', 'Sai']);
```

Writing `items[0]`, `items[1]`... by hand breaks as soon as something is added. The
element to repeat gets **`v-for`**, a loop right in the template:

```vue
<ul>
  <li v-for="item in items">{{ item }}</li>
</ul>
```

Add a value to the array and a new `<li>` appears. Nothing else needs to change.

Adding started as an inline `items.push(message)` on the button, then moved into a
function once it grew past one statement:

```js
function add(){
  if(message.value.trim() !== '') {
    items.value.push(message.value.trim());
  }
  message.value = '';
}
```

Step by step:

- **`.value` everywhere** in the script, for both refs (otherwise: *items.push is not a
  function*).
- **`message.value = ''`** empties the text box after adding, because `v-model` works in
  both directions. No need to find the input.
- **The empty check** stops blank items. But a text of only spaces is not empty, so
  **`trim()`** removes whitespace from both ends first, and an all-space text becomes `''`.
- **`@keydown.enter="add"`** on the input: pressing Enter adds the item too, so the mouse
  is optional.

## ✅ Takeaways

1. **`ref()` makes a value reactive**; a plain variable changes but the page does not
   follow.
2. **`@` is `v-on`, `:` is `v-bind`.** Mustaches are for content, `:` for attributes.
3. **`v-model` = `:value` + `@input`**, binding both directions.
4. **In `<script setup>` use `.value`**, in the template do not.
5. **`v-for` repeats an element per array item**; push to the array and the page updates.
6. **`trim()` before checking for empty**, and `@keydown.enter` for keyboard users.
