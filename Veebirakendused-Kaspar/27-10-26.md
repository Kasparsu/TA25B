## 🗂️ Topics Covered

> 🧭 Last time the modals were built. This time they moved to their own page next to the
> shopping list, and the question was how to switch between the two. First by hand, with a
> home-made `Tabs` component and Vue's `<component :is>`, then the proper way: **Vue
> Router**, which makes a single page application behave like a site with many pages.

### 1. 🗂️ A `Tabs` component from Bulma

The modal demo moved into `src/pages/Modals.vue` (imports fixed to `../components/...`,
like last week), and `App.vue` was emptied again for something new: Bulma's **tabs**
(<https://bulma.io/documentation/components/tabs/#alignment>). There are many variants
(alignment, sizes, icons, styles); the centred one was used here, but try others.

This time the markup went straight into a component, `src/components/Tabs.vue`. The tab bar
was put **outside** the `container`: the container limits the width, and the tab line looks
better running across the whole screen.

The titles come in as a prop, and the one `<li>` is repeated with `v-for`. To know which tab
is active, a `true`/`false` flag (as with the modal) is not enough, since there are many
tabs. The active tab is a **number**, its position in the list, and `v-for` can hand out
that position as a second value:

```vue
<script setup>
defineProps(['titles', 'active']);
</script>
<template>
    <div class="tabs is-centered">
        <ul>
            <li v-for="(title,key) in titles" :class="{'is-active': active === key}" @click="$emit('change', key)">
                <a>{{ title }}</a>
            </li>
        </ul>
    </div>
</template>
```

- **`(title, key)`**: the item and its index (0, 1, 2...). Printing the key next to the
  title made that visible first.
- **`active === key`** puts `is-active` on exactly one tab.
- **`$emit('change', key)`**: the prop cannot be changed inside the component (last week's
  lesson), so a click emits an event, and this time it carries a value: which tab was
  clicked.

In the parent, the value of an emitted event is available as **`$event`**:

```html
<Tabs :titles="tabTitles" :active="activeTab" @change="activeTab=$event"></Tabs>
```

With a `contents` array in the same order as the titles, `{{ contents[activeTab] }}` showed
the matching text under the tabs.

### 2. 🔀 Switching whole pages with `<component :is>`

Text is nice, but the goal was to switch between the real pages. Importing `ToDo` and
`Modals` and putting them into the array only printed a big JSON-ish dump: a component is
just an object, and `{{ }}` writes it out as text. To **render** a component chosen at run
time, Vue has a special built-in component:

```js
import ToDo from './pages/ToDo.vue';
import Modals from './pages/Modals.vue';

let contents = [
    ToDo,
    Modals,
];
```

```html
<component :is="contents[activeTab]"></component>
```

The console also had a warning: Vue received a component that was made a **reactive
object**. The array was still wrapped in `ref()` from the text example. Components should
not be reactive, and nothing changes the array anyway, so a plain array fixed it.

![Components in a ref](https://api.memegen.link/images/yodawg/Yo_dawg,_I_heard_you_like_components/so_I_put_components_in_your_ref.png)

### 3. 📄 What "single page application" means

Clicking tabs makes it feel like moving between pages, but nothing is loaded: it is the same
`index.html`, all the code is already in the browser, and Vue just swaps which component is
shown. That is a **SPA**, a *single page application*, and that is also why it is fast: no
new page, no request to the server.

![SPA](https://api.memegen.link/images/morpheus/What_if_I_told_you/you_never_left_index.html.png)

Doing this by hand gets tedious, and the address bar never changes, so refresh always
returns to the first tab. Every frontend framework has a ready solution called a
**router**. The name comes from network routers: the box at home sends each packet to the
right place (the game traffic to the game server, the stream to Netflix) and the answers
back to the right computer. A frontend router looks at the address bar and decides which
page component to show.

### 4. 📦 Installing Vue Router

```
bun add vue-router
```

(`bun install vue-router` or `npm install` work the same.) A word of warning about
installing packages: copy the name from the official docs rather than typing it. Attackers
publish packages with almost the same name (a missing dash, one letter changed) that do the
same thing plus something nasty, like sending card details from your payment page to their
server. That is called *typosquatting*.

Anyone pulling this commit at home must run `bun install` after `git pull`, because
`package.json` changed.

### 5. 🛣️ Routes, `RouterLink` and `RouterView`

The getting-started guide (<https://router.vuejs.org/guide/#Creating-the-router-instance>)
was copied into `src/index.js` and adapted: our pages are `ToDo` and `Modals`, not `Home`
and `About`. A route is a path plus the component to show for it, and `app.use(router)`
goes between creating and mounting the app:

```js
import { createMemoryHistory, createWebHashHistory, createWebHistory, createRouter } from 'vue-router';

import ToDo from './pages/ToDo.vue';
import Modals from './pages/Modals.vue';

const routes = [
  { path: '/', component: ToDo },
  { path: '/modals', component: Modals },
];

export const router = createRouter({
  history: createWebHistory(),
  routes,
});

import App from './App.vue';

const app = createApp(App);
app.use(router);
app.mount('#app');
```

`App.vue` lost the tabs (`git` still has them) and got the guide's example: links, the
current path, and the spot where the page goes:

```html
<p><strong>Current route path:</strong> {{ $route.fullPath }}</p>
<nav>
    <RouterLink to="/">Go to ToDo</RouterLink>
    <RouterLink to="/modals">Go to Modals</RouterLink>
</nav>

<main>
    <RouterView />
</main>
```

**`RouterView`** is where the component of the current route is drawn. Neither it nor
`RouterLink` needs importing.

### 6. #️⃣ Three kinds of history

The `history` option decides how the router keeps track of where you are:

- **`createMemoryHistory`** (the guide's default) keeps it in memory only: the links work,
  but a refresh always lands back on the first page.
- **`createWebHashHistory`** puts the page after a `#` in the URL (`/#/modals`), so refresh
  remembers it. The `#` part is old and familiar: documentation sites use it for links to a
  spot on the page (`#form-addons` in the Bulma links). It points to an element `id`, the
  browser never reloads for it and the server never sees it, so it works on **any** server.
- **`createWebHistory`** gives clean URLs like `/modals`. The catch: the server must answer
  every unknown path with `index.html` instead of a 404. Vite's dev server does that out of
  the box; a random server may need configuring.

![History modes](https://api.memegen.link/images/panik-kalm-panik/Refresh_sends_you_back_to_ToDo/createWebHashHistory_remembers_the_page/Now_there_is_a_~h_in_every_URL.png)

### 7. 🔗 Why `RouterLink` and not a plain `<a>`

Plain `<a href="#/modals">` links work too. So why bother? With web history the difference
shows: a normal link makes the browser **load the page again** (watch the refresh icon and
the tab title flicker), asks the server, re-runs all the JavaScript, and loses any state.
With DevTools throttled to 3G the screen even goes white for a moment.

A `RouterLink` renders a normal `<a>`, but catches the click with `preventDefault`, changes
the address bar with JavaScript and swaps the component. Nothing is reloaded. It also adapts
to whichever history mode is in use, so switching modes does not mean rewriting links.

## ✅ Takeaways

1. **`v-for="(item, key) in list"`** gives the index too; the active tab is a number.
2. **`$emit('change', key)`** sends a value up; the parent reads it as `$event`.
3. **`<component :is="...">`** renders a component chosen at run time. Do not put
   components in a `ref`.
4. **A SPA never leaves `index.html`**; a router maps the address bar to page components.
5. **Copy package names from the docs** (typosquatting), and `bun install` after pulling a
   changed `package.json`.
6. **Routes + `app.use(router)` + `RouterView` + `RouterLink`**; memory history forgets on
   refresh, hash history works everywhere, web history needs the server to serve
   `index.html`.
7. **`RouterLink` switches pages without a reload**; a plain `<a>` reloads everything.
