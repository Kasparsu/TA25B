## 🗂️ Topics Covered

### 1. 🧰 CSS Frameworks

Writing every button, form and layout yourself is a lot of CSS for results that usually end up
worse than a framework's. A **CSS framework** gives you ready-made components and a layout
system.

There are many of them, with different philosophies: component libraries like Bulma and
Bootstrap, utility-first ones like Tailwind, and minimal classless ones that just style plain
HTML.

| Link | What it is |
|---|---|
| <https://github.com/troxler/awesome-css-frameworks> | A large curated comparison: worth a browse before picking one |

### 2. 🅱️ Bulma

```bash
bun add bulma
```

**Bulma is class-based and pure CSS**: no JavaScript at all, which makes it a clean fit here.
You describe what something *is* with classes:

```html
<button class="button is-primary">Primary</button>

<div class="notification is-primary">
    Lorem ipsum dolor sit, amet consectetur adipisicing elit…
</div>
```

The pattern is consistent: a **component** class (`button`, `notification`) plus **modifier**
classes (`is-primary`, `is-large`, `is-light`). Once you've seen it on one component, the rest
of the library reads the same way.

| Link | What it is |

| <https://bulma.io/> | Bulma: documentation and every component |

### 3. 🎨 Customising It Through Sass

This is why Sass was installed the week before. Rather than overriding Bulma's CSS after the
fact, you **compile Bulma with your own values**:

```scss
@use "bulma/sass" with (
    $primary: coral,
);
```

**`@use … with (…)`** loads a Sass module and overrides its variables *before* it compiles. So
every `is-primary` in the project (buttons, notifications, everything) becomes coral. One
line, whole site.

**Compare the alternatives:**

| Approach | Result |
|---|---|
| Override afterwards with more CSS | You fight specificity, and miss places |
| Edit Bulma's own files | Breaks the moment you update it |
| **`@use … with`** | Bulma compiles itself using your values |

> 🧠 This is the same argument as `$bgcolor` and `color.scale` last week, scaled up: change the
> important value in one place and let everything derived from it follow. The work happens at
> build time; the browser just gets CSS.

## ✅ Takeaways

1. **Use a CSS framework** rather than writing every component from scratch.
2. **Bulma is pure CSS**: component class plus `is-*` modifiers, no JavaScript.
3. **`@use "bulma/sass" with ($primary: coral)`** rebuilds the framework with your values:
   don't override afterwards, and never edit its files.
4. **Theming is a build-time concern.** The browser receives finished CSS.
