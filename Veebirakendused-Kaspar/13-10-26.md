### 1. 🧱 Items as objects (and a multi-cursor trick)

A string can only hold the text. To know whether something is bought, each item became an
**object** with an `id`, the `text` and an `isDone` flag:

```js
let i = 1;
let items = ref([
    {id: i++, text: 'Piim', isDone: false},
    {id: i++, text: 'Viin', isDone: true},
    {id: i++, text: 'Õlu', isDone: false},
    {id: i++, text: 'Sai', isDone: true},
]);
```

`i++` hands out the current value and then increases it, so the ids come out 1, 2, 3, 4
without typing them. A couple of items start as `true` so there is something to test with.

Rewriting four lines the same way is a job for **multiple cursors**: hold **Alt** and click
to place a cursor on every line, then type once. The lines have different lengths, so the
arrow keys leave the cursors out of step. **End** sends every cursor to the end of its own
line and **Home** to the start.

![Multi-cursor](https://api.memegen.link/images/feelsgood/Alt_and_click,_then_End/Every_cursor_at_the_end_of_its_own_line.png)

New items still went in as plain strings and showed up differently from the rest, so `add`
now pushes an object too. Something just added is not done yet:

```js
items.value.push({id: i++, text: message.value.trim(), isDone: false});
```

### 2. ☑️ Showing the text and a checkbox

Printing `{{ item }}` now dumps the whole object. The template prints only `item.text`, and
a checkbox is bound to `isDone` with `v-model`:

```html
<li v-for="item in items" :key="item.id">
    {{ item.text }}
    <input type="checkbox" v-model="item.isDone">
</li>
```

Ticking a box changes the data, but on its own nothing on the page shows that yet. That is
what the next step is for.

### 3. 🧮 `computed` and `filter`: done and to-do lists

The list was copied twice more under the headings *Done items* and *ToDo items*. Those two
lists are not new data; they are worked out from `items`. That is a **computed** value: it
is calculated from other reactive values and recalculated when they change. Typing
`computed` and pressing Enter lets the editor add the import.

```js
let doneItems = computed(() => items.value.filter(item => item.isDone));
let toDoItems = computed(() => items.value.filter(item => !item.isDone));
```

- **`filter`** goes through the array and builds a new one. The function it gets is called
  for every element; return `true` and the element stays, `false` and it is left out.
  `isDone` is already a boolean, so it can be returned as is.
- **`!`** flips it, so the to-do list keeps exactly the opposite.
- The function started out as a full anonymous function with braces and `return`, and was
  shortened step by step: an **arrow** instead of `function`, no brackets around a single
  parameter, and no braces or `return` when the body is one expression.
- Inside the script it is **`items.value`**, as always with a ref.

Tick a box and the item jumps between the lists by itself.

![filter](https://api.memegen.link/images/soup-nazi/isDone_is_false~q/No_Done_list_for_you!.png)

### 4. 🔑 The bug that `:key` fixes

A question to the class: can anyone spot the bug? Untick the first item in the *Done* list
and it disappears from there, as it should. But the item that moves up into its place now
shows an **empty** checkbox, even though it is done. The data is right; only the picture is
wrong.

The reason: while a `v-for` list only grows, Vue manages fine. Once items disappear or
change order, it reuses the elements it already drew and can attach the wrong state to the
wrong row. **`:key`** gives every element a unique value so Vue knows which one is which.
That is what the `id` was for:

```html
<li v-for="item in doneItems" :key="item.id">
```

Rule of thumb: a `v-for` always gets a `:key`.

![key](https://api.memegen.link/images/dbg/The_data:_correct/The_checkbox:_on_the_wrong_item.png)

### 5. 🧩 Don't repeat yourself: an `ItemList` component

The template now had the same block three times, only the heading and the list differing.
Code like this is called **WET** (*write everything twice*), the opposite of **DRY**
(*don't repeat yourself*). Once you write the same thing for the second or third time,
look for a way to write it once and reuse it.

In Vue that is a **component**. The block moved into its own file, `src/ItemList.vue`
(component names start with a capital letter, every following word too):

```vue
<script setup>
defineProps(['items', 'title']);
</script>
<template>
    <h1>{{ title }}</h1>
    <ul>
        <li v-for="item in items" :key="item.id">
            {{ item.text }}
            <input type="checkbox" v-model="item.isDone">
        </li>
    </ul>
</template>
```

At first the component showed headings but no lists, and the console said why: `items` is
not defined. `App.vue` knows what `items` is, but the component only sees what it is given.
**`defineProps`** lists what it accepts. A component is used like an HTML element, and
props are like its attributes:

```html
<ItemList :items="items" title="All items"></ItemList>
<ItemList :items="doneItems" title="Done items"></ItemList>
<ItemList :items="toDoItems" title="ToDo items"></ItemList>
```

- **`:items`** (with the colon, `v-bind`) passes the value of a variable.
- **`title`** without a colon passes the text as written, which is all a heading needs.

The editor may add `import ItemList from './ItemList.vue';` when you type the tag; if it
does not, add it yourself, otherwise Vue does not know the tag.

## ✅ Takeaways

1. **Objects carry more than a string**: `id`, `text`, `isDone`; `i++` hands out ids.
2. **Alt + click, End, Home**: edit many lines at once.
3. **`computed` + `filter`** derive new lists that update by themselves; `!` flips a
   boolean.
4. **A `v-for` always gets a `:key`**, or Vue can show the right data on the wrong row.
5. **WET code becomes a component**: `defineProps` declares what it accepts, `:` passes a
   variable, no colon passes text.
6. **Homework**: importance, sorting and colours on the item list, handed in as a GitHub
   link by 20.10.
