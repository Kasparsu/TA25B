## 🗂️ Topics Covered

> 🧭 Vue Router worked last time, but with plain text links. This lesson turned the Bulma
> tabs into a `RouterTabs` component that builds the menu from the router itself, then let
> the router find the pages on its own from the `pages/` folder. The last part started a
> `Btn` component and showed how props can be described and validated.

### 1. 🗂️ `RouterTabs`: a menu built from the routes

The tabs component from last time was made for clicking through an array. For the router a
specific version is simpler, so `src/components/RouterTabs.vue` got a fresh copy of Bulma's
centred tabs (<https://bulma.io/documentation/components/tabs/#alignment>), and `App.vue`
shrank to the tabs plus the `RouterView`.

Writing a `RouterLink` per page by hand works, but every new page would mean another line.
The router already knows all the routes. Vue Router offers two functions for the script:

- **`useRouter()`**: the whole router object, with functions for navigating and
  **`getRoutes()`**, the list of registered routes.
- **`useRoute()`**: the route you are on right now (also inside the router as
  `currentRoute`).

Logging them to the console showed what is inside: each route has a `path`, the
`component`, and a `name` that was `undefined`. Giving the routes a name in `index.js`
filled that in:

```js
const routes = [
  { path: '/', component: ToDo, name: 'To Do'},
  { path: '/modals', component: Modals, name: 'Modals' },
];
```

In the template those functions are not even needed: the router makes both available as
**`$router`** and **`$route`**. The script part stayed only as a commented-out example.

```html
<div class="tabs is-centered">
    <ul>
        <li v-for="route in $router.getRoutes()" :class="{'is-active': route.path === $route.path}">
            <RouterLink :to="route.path">{{ route.name }}</RouterLink>
        </li>
    </ul>
</div>
```

- **`RouterLink`** instead of `<a>`: it has `to` instead of `href` and does not reload the
  page (last lesson).
- **`route.path === $route.path`**: the tab being drawn is the active one when its path is
  the current path. Unlike the hand-made tabs, the active tab survives a refresh.

### 2. 📦 The container goes into `App.vue`

Both pages wrapped their content in the same `<div class="container content mt-2">`. Doing
that on every future page is repetition again, so it moved around the `RouterView` in
`App.vue` and came out of the pages:

```html
<RouterTabs></RouterTabs>
<div class="container content mt-2">
    <RouterView />
</div>
```

### 3. 📂 Routes from files: `import.meta.glob`

Adding a page still meant two edits: an import and a route. Vite can import a whole folder
at once. **`import.meta.glob`** returns an object whose keys are the file paths
(`./pages/Modals.vue` and so on) and whose values are functions that load the file:

```js
const pages = import.meta.glob('./pages/*.vue');

const routes = [];
for(let page in pages) {
  let name = page.replace('./pages/', '').replace('.vue', '');
  let path = '/' + name.toLowerCase();
  if(routes.length === 0) {
    path = '/';  
  }
  routes.push({ path, name, component: pages[page]});
}
```

- **`for ... in`** walks over the object's keys. (`in` gives the keys, `of` the values;
  everyone mixes them up, the console settles it.)
- The **name** is the file name without the folder and the `.vue` ending, via two
  `replace` calls.
- The **path** is `/` plus the lowercase name. Uppercase would work in the address bar too,
  but lowercase is the convention.
- **`{ path, name, component }`** is shorthand: a key with the same name as the variable
  can be written once.
- The **first** route becomes the home page `/`, otherwise there is no home page at all.

Now a new page is just a file. An empty `src/pages/Buttons.vue` appeared in the menu by
itself.

![Auto routes](https://api.memegen.link/images/stonks/New_file_in_pages~s/New_tab_in_the_menu.png)

The catch is honest: the files come in **alphabetical** order, so the home page is whichever
name comes first. `Buttons` now beats `Modals` and `ToDo`. Systems with file-based routing
usually solve this with a fixed name such as `index` for the home page. For a folder of
examples it is good enough and saves time.

![Home page](https://api.memegen.link/images/harold/Buttons.vue_is_now_the_home_page/because_B_comes_before_M.png)

### 4. 🔘 A `Btn` component (and why not `Button`)

Components do not have to be complicated. Bulma's button
(<https://bulma.io/documentation/elements/button/>) is just a `button` class plus extras:
colours (`is-primary`, `is-danger`...), light and dark shades, sizes, `is-fullwidth`,
outlined and inverted styles, states. A small component can make those nicer to use.

The first idea, `Button.vue`, is a trap. Vue lets you write component names in several
ways, also in lowercase, so `<Button>` and the HTML `<button>` are one letter apart and easy
to confuse. Depending on how strict the compiler is set, it may even complain. Avoid naming
components after existing HTML elements (`button`, `header`, `footer`, `main`...). Two
common ways out: a **prefix** (many component libraries put their own letters in front of
every component), or a short name that is not an HTML element. Here: `Btn`.

![Button vs button](https://api.memegen.link/images/spiderman/~lButton~g/~lbutton~g.png)

The button text comes through a **`<slot>`**, so it is written between the tags like on a
normal button.

### 5. ✅ Props as an object: type, default, validator

Passing Bulma classes in as a `class` prop worked but says little: you must know the class
names and type `is-` every time. A `color` prop is nicer: the component adds the `is-`
itself, combined in a `computed`. `class` is a reserved word in JavaScript, which caused a
hiccup until the props were read through the object `defineProps` returns.

So far props were a list of names that accept anything. **`defineProps` also takes an
object**, and each prop can describe itself:

```js
let props = defineProps({
    class: {
        type: String,
        default: ''
    },
    color: {
        type: String,
        validator(value, props) {
            // The value must match one of these strings
            return [
                'success',
                'warning',
                'danger',
                'info',
                'link',
                'primary',
                'ghost',
                'text',
                'black',
                'dark',
                'light',
                'white',
            ].includes(value)
        }
    }
});

let cssClass = computed(() => props.class + ' is-' + props.color)
```

```html
<button class="button" :class="cssClass">
    <slot></slot>
</button>
```

- **`type`**: what kind of value is allowed (`String`, `Number`...). For only that, a short
  form `color: String` works too.
- **`default`**: used when the prop is not given. Without it, a missing `class` showed up as
  `undefined` in the class list.
- **`required: true`**: Vue warns in the console when the prop is missing.
- **`validator`**: a function that gets the value (and all props, so rules like "small
  buttons only in these colours" are possible) and returns `true` if it is fine. Here,
  `includes` checks that the colour is one Bulma knows. The example came from the Vue docs
  (<https://vuejs.org/guide/components/props.html#prop-validation>), with the list
  completed.

A made-up colour now gives a console warning: *Invalid prop: custom validator check failed
for prop "color"*. This matters most when other people (or you, months later) use the
component.

```html
<Btn color="primary">Cool button</Btn>
```

## ✅ Takeaways

1. **`$router.getRoutes()` and `$route`** build a menu that always matches the routes;
   give routes a `name`.
2. **`RouterLink :to`** and `route.path === $route.path` for the active tab.
3. **Shared layout goes around `RouterView` in `App.vue`**, not into every page.
4. **`import.meta.glob('./pages/*.vue')`** turns files into routes; the first file
   alphabetically becomes `/`.
5. **Do not name components after HTML elements**: `Btn`, not `Button`.
6. **Props as an object**: `type`, `default`, `required` and a `validator` that warns about
   bad values.
