### 1. 🥟 `bun init`

```bash
bun init
```

Scaffolds a project. What it leaves behind:

| File | Purpose |
|---|---|
| `package.json` | Project name, type, dependencies |
| `bun.lock` | **Exact** versions of everything installed |
| `index.js` | Entry point |
| `tsconfig.json` | TypeScript settings (Bun runs TS directly) |
| `.gitignore` | What Git should ignore |

**The `.gitignore` is worth reading**, because it explains what *not* to commit:

```
node_modules     # dependencies: reinstallable, huge
dist, out        # build output: regenerated
.env             # secrets: never commit these
*.log            # logs
.idea, .DS_Store # editor and OS clutter
```

> 🔑 **`bun.lock` you DO commit**, even though `node_modules` you don't. The lockfile records
> the exact versions, so everyone installs the identical tree. That's the difference between
> "it works on my machine" and it working on everyone's.

**Running something:**
```js
console.log("Hello via Bun!");
import fs from "fs";

let text = fs.readFileSync("./index.js", "utf-8");
console.log(text);
```

A program reading its own source: a neat demonstration that this is JavaScript **outside the
browser**, with access to the filesystem. `fs` is a built-in module; `"utf-8"` asks for text
rather than raw bytes.

### 2. ⚡ Vite

Bun runs JavaScript. **Vite** is what serves it to a browser and bundles it for production.

```bash
bun add vite
```

```json
"scripts": {
    "dev": "vite",
    "build": "vite build"
}
```

Run with `bun run dev` (a dev server with hot reload) and `bun run build` (production bundle).

**The HTML entry point:**
```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
</head>
<body>
    <script type="module" src="./src/index.js"></script>
</body>
</html>
```

**`type="module"`** is the important attribute: it's what makes `import` work in the browser.

**ES modules, across two files:**

```js
// src/math.js
export default {
    add(a, b) {
        return a + b;
    }
}
```

```js
// src/index.js
import math from './math.js';

let answer = math.add(2, 4);
console.log(answer);
```

`export default` publishes one thing from a file; `import math from './math.js'` pulls it in
under a name **you** choose: with a default export, the name is yours to pick.

> 🧠 This is the point of a build tool: code split across many small files, assembled into
> something the browser can load.

### 3. 🎨 Sass

```bash
bun add sass-embedded
```

Vite understands `.scss` with no configuration beyond installing the compiler:

```html
<link rel="stylesheet" href="./src/style.scss">
```

```scss
@use 'sass:color';

$bgcolor: gray;

body {
    background: color.scale($bgcolor, $lightness: -30%);
}
```

**What Sass adds over plain CSS:**

| Feature | Shown here |
|---|---|
| **Variables** | `$bgcolor: gray`: define once, use everywhere |
| **Modules** | `@use 'sass:color'` pulls in Sass's built-in colour module |
| **Colour functions** | `color.scale(…, $lightness: -30%)`: derive one colour from another |

**Why `color.scale` rather than typing a darker grey:** change `$bgcolor` and everything
derived from it follows. That's the whole argument for a preprocessor: say the important
thing once.

**And it all happens at build time.** The browser receives ordinary CSS; no computation
happens on the user's machine.

## ✅ Takeaways

1. **Commit `bun.lock`, ignore `node_modules`.** The lockfile is what makes installs identical.
2. **Never commit `.env`.**
3. **`type="module"`** is what lets the browser use `import`.
4. **`export default` / `import x from`**: split code into small files.
5. **Sass gives you variables and colour functions**, resolved at build time so the user pays
   nothing.
